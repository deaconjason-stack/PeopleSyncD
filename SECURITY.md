# Security Policy

## Reporting a vulnerability

Do not disclose suspected vulnerabilities in a public issue. Contact the repository owner privately through GitHub's security reporting features when available.

Include:

- affected component and version or commit
- reproduction steps
- expected and observed behavior
- potential impact
- any proof-of-concept material that can be shared safely

## Sensitive data

Never commit passwords, tokens, API keys, private keys, employee records, tax data, identity documents, medical or accommodation information, background-check reports, or customer production data.

## Response principles

Reports are acknowledged, triaged, contained, remediated, tested, documented, and disclosed responsibly. No compliance or certification claim may be made without supporting evidence.

## Supported versions

No production version is currently certified. Support declarations will be published in release evidence when a production release is approved.

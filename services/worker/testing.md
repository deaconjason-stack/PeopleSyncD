# Worker Verification Specification

## Purpose

Define automated verification required before Worker service implementation can be certified.

## Required suites

- Unit tests for fields, validation, invariants, and state transitions
- API contract tests against OpenAPI
- Event contract tests against AsyncAPI
- Database migration and constraint tests
- Row-level tenant-isolation tests
- Own, direct-report, department, and organization permission tests
- Cross-tenant identifier rejection tests
- Historical-record preservation tests
- Optimistic-concurrency and stale-write tests
- Audit emission and denial-evidence tests
- Outbox delivery, retry, and idempotency tests
- Performance-budget tests once budgets are approved
- Accessibility and UI acceptance tests for Worker screens
- Domonique 2.0 authorization and AI-disabled operation tests

## Evidence rules

Each automated test receives a permanent `PSD-TEST-*` identifier and links to one or more requirements. Counts, pass status, and coverage are generated by CI and attached to release certification; they are never manually asserted in this document.

## Certification gate

Unresolved critical tenant-isolation, authorization, data-integrity, audit, migration, or contract defects block release.

# M2.1 Identity and Tenant Vertical Slice

## Goal

Deliver the first complete PeopleSyncD platform workflow on the .NET and Next.js foundation.

A founder can create an organization and owner account, authenticate, list authorized organizations, select an active organization, receive tenant-scoped permissions, and call a tenant-bound protected API.

## Delivered behavior

- Atomic owner, organization, and owner-membership provisioning.
- ASP.NET Core Identity password hashing and lockout policy.
- Generic invalid-credential responses that resist account enumeration.
- User access tokens before tenant selection.
- Active-membership verification during tenant selection.
- Tenant-scoped JWT claims for membership, organization, role, and permissions.
- Permission policies for organization, membership, and employee capabilities.
- Explicit organization-identifier comparison to prevent cross-tenant object access.
- Next.js registration, login, organization selection, and current-session workspace.
- PostgreSQL additive migration for identity and organization-membership fields.
- Domain, persistence, API, integration, OpenAPI, web, audit, and container verification.

## API workflow

1. `POST /api/v1/auth/register-tenant` creates the first owner and tenant.
2. `POST /api/v1/auth/login` returns an authenticated user token without tenant permissions.
3. `GET /api/v1/auth/organizations` lists available memberships.
4. `POST /api/v1/auth/select-organization` returns a tenant-scoped token.
5. `GET /api/v1/auth/me` returns the validated identity and optional tenant context.
6. `GET /api/v1/organizations/{id}` requires the organization-read permission and an exact selected-tenant match.

## Release boundary

M2.1 is an implemented and tested platform foundation. It is not a production-certified customer release. Email verification delivery, refresh-token rotation, MFA enrollment, federation, SCIM, administrative membership invitations, and customer deployment approval remain later milestones.

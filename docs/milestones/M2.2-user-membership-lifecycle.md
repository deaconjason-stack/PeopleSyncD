# M2.2 — User Administration and Membership Lifecycle

## Objective

Turn M2.1 identity and tenant selection into an administrable organization lifecycle without weakening tenant isolation.

## Implemented scope

- single-use, seven-day organization invitations
- owner and administrator membership administration
- role changes among administrator, manager, member, and auditor
- active, suspended, and revoked membership transitions
- final-active-owner protection
- immediate stale tenant-token rejection after membership or role change
- email verification gating before tenant token issuance
- ASP.NET Core Identity lockout accounting
- 30-day rotating refresh-token families with reuse detection
- refresh-session revocation when membership authorization changes
- security audit records for sensitive identity and membership actions
- MFA-ready login boundary that refuses password-only authentication when a second factor is enrolled
- organization-user and invitation acceptance web workspaces
- versioned PostgreSQL migration contract and CI schema validation

## Deliberate boundaries

This milestone does not implement a complete MFA challenge. If ASP.NET Core Identity reports `TwoFactorEnabled`, password-only login is rejected with an MFA-required outcome. TOTP/WebAuthn enrollment, challenge verification, recovery codes, and trusted-device policy belong to M2.3.

Development email delivery uses a local `.local-email` outbox that is excluded from source control. Production startup must not use that transport; a production identity-notification provider remains required.

Browser access tokens remain in `sessionStorage` only for the controlled engineering demonstration. Refresh tokens are returned by the API but are not persisted by the M2.2 browser client. Production browser authentication still requires a hardened BFF and secure HTTP-only cookie design.

- audited NuGet restore including the pinned Fido2 dependency;
- strict .NET formatting and analyzer build;
- all .NET tests with coverage;
- passkey registration-option policy tests;
- generic unavailable behavior for unknown/unregistered passkey login;
- privileged-authentication freshness tests;
- refresh-preserved authentication-time tests;
- deterministic Next.js typecheck and production build;
- high-severity npm audit;
- PostgreSQL migration execution and M2.4 passkey-schema assertions;
- OpenAPI linting;
- Docker Compose validation;
- API and web image builds; and
- all repository governance, traceability, security, corpus, Markdown, and blueprint gates applicable to the final head.

## Hardware-in-the-loop qualification

Repository CI does not possess a physical WebAuthn authenticator. Passing repository gates therefore verifies the compiled WebAuthn integration, policy options, browser serialization contract, server persistence, and negative/security boundaries; it does not claim a completed physical-authenticator acceptance matrix.

## Release boundary

Even after engineering verification, M2.4 will not constitute production certification. Production RP/origin configuration, live-authenticator compatibility testing, browser session hardening, operational review, penetration testing, signed packaging, deployment approval, and regulatory certification remain separate gates.

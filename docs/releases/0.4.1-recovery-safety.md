# PeopleSyncD Genesis 0.4.1 — Recovery and Administrative Safety

## Classification

Unsigned internal engineering release. Not certified for customer production deployment.

## Implemented

- Monotonic TOTP counter persistence and replay denial.
- Single-use recovery-code consumption.
- Recovery-driven session rotation and old-session invalidation.
- Last active Founder protection in application and PostgreSQL.
- Immediate non-Founder session revocation after suspension or termination.
- Dedicated production runtime database identity requirement.
- Controlled runtime-login provisioning script.
- Expanded cryptographic, API, PostgreSQL, configuration, build, and packaging tests.

## Security boundaries

Recovery-code use requires an already authenticated, authorized session. This release does not provide unauthenticated account recovery, support-assisted identity proofing, MFA reset, or recovery-code replacement.

WebAuthn ceremonies, federated identity, adaptive risk, independent penetration testing, Authenticode signing, and production certification remain incomplete.

## Compatibility

- Node.js 22
- PostgreSQL 16
- Windows 10 and Windows 11 internal unsigned installer
- Existing Genesis 0.4.0 database upgraded through migration `0005_phase7b2b_recovery_replay_founder.sql`

## Upgrade summary

1. Back up the PostgreSQL database.
2. Apply migrations with the migration-authorized identity.
3. Provision a dedicated application LOGIN with `scripts/database/provision_runtime_login.sql`.
4. Configure `PEOPLESYNCD_RUNTIME_DATABASE_URL` and direct role mode.
5. Deploy API and client artifacts.
6. Run readiness, recovery, replay, membership, and tenant-isolation acceptance tests.

## Known limitations

- The Windows installer is unsigned.
- Recovery codes cannot yet be regenerated through a governed workflow.
- WebAuthn enrollment records are not usable authenticators.
- External identity-provider login is not implemented.
- The package is not certified for healthcare, government, or customer production use.

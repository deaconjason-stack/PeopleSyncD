# PeopleSyncD 0.2.3 — M2.3 Engineering Milestone

## Scope

M2.3 advances the .NET platform from an MFA-ready fail-closed boundary to executable TOTP multi-factor authentication, recovery codes, session assurance, and user-controlled session revocation.

## Implemented engineering behavior

- TOTP authenticator enrollment with possession verification before activation;
- monotonic accepted-counter tracking to deny reuse of an already accepted TOTP moving factor;
- five-minute, hash-only, single-use MFA challenge secrets;
- password login that returns an MFA challenge instead of authority when MFA is enrolled;
- TOTP and recovery-code challenge completion;
- ten hash-only, single-use recovery codes with whole-batch regeneration;
- MFA activation that revokes earlier refresh sessions;
- `pwd` and `mfa` assurance on access and refresh sessions;
- live session-family validation on authenticated requests;
- session inventory, per-family revocation, and revoke-other-sessions control;
- recent user security-event visibility;
- a browser Security Center for authenticator setup, recovery-code handling, session management, and fresh MFA verification;
- PostgreSQL M2.3 migration contract for challenges, recovery codes, TOTP counter state, and assurance metadata;
- OpenAPI 0.2.3 contract;
- automated API behavior, browser build, package audit, database-schema, and container validation gates.

## Security notes

Recovery codes and MFA challenge bearer secrets are stored only as SHA-256 hashes. TOTP shared secrets are not hash-only because TOTP verification requires the recoverable shared secret; production custody of those secrets remains subject to database encryption, backup protection, and key-management release gates.

M2.3 includes a fresh step-up challenge mechanism but does not yet impose maximum-authentication-age policy on individual business operations.

## Explicit exclusions

M2.3 does not implement WebAuthn/passkeys and does not claim phishing-resistant authentication. It also does not claim production browser refresh-token custody, production secret/key custody, operational certification, signed packaging, or production deployment approval.

This is an engineering milestone, not a production-certified customer release.

# PeopleSyncD Engineering Documentation

This directory contains the authoritative PeopleSyncD engineering corpus.

## Corpus sections

- `governance/` — authority, ownership, lifecycle, change, and release governance
- `standards/` — mandatory engineering and documentation standards
- `requirements/` — requirements as code and controlled registries
- `specifications/` — platform, service, module, UI, AI, and data specifications
- `architecture/` — system architecture, bounded contexts, and diagrams
- `adr/` — architecture decision records
- `rfc/` — requests for change
- `security/` — security architecture, controls, reviews, and evidence
- `api/` — OpenAPI contracts
- `asyncapi/` — event contracts
- `database/` — database specifications and migration guidance
- `testing/` — verification strategy and test standards
- `operations/` — deployment, observability, recovery, and support
- `certification/` — release evidence and certification controls
- `licensing/` — editions, entitlements, activation, and commercial rights
- `release/` and `releases/` — release process and version-specific plans

## Authoritative lifecycle

`Idea → RFC → ADR → Requirement → Specification → Contract → Implementation → Automated Tests → Certification → Release`

A document or capability is not authoritative merely because it exists. Its status, approval, version, and traceability determine its authority.

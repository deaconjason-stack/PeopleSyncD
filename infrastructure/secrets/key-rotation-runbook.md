# Key Rotation Runbook

1. Identify the key, owner, dependents, data class, and urgency.
2. Create replacement material through the approved key service.
3. Stage dual-read or dual-verification where supported.
4. Deploy the new key reference using controlled configuration.
5. Verify health, decryption, signatures, and audit delivery.
6. Revoke the previous key after the approved overlap period.
7. Record affected releases, customers, incidents, and evidence.
8. Confirm backups and disaster-recovery environments use the correct key state.

Emergency rotation follows incident response and may shorten overlap after impact analysis.
